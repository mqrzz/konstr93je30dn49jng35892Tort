Send

One request. Signed and queued.

Send a message with a single HTTP call and your API key. Geserd checks that the sender domain is verified, signs the message with DKIM and places it in the queue, so your application never waits for the receiving server to answer. The response contains an id that you can use to look up the message and its events at any time.

  • Plain JSON with HTML and text bodies
  • Reply-To, custom headers and attachments
  • An id you can look up later

Reliability

Retries, so a busy server does not lose your mail

Receiving servers sometimes answer with a temporary error, for example when they are busy or when greylisting is active. Geserd keeps the message in the queue and tries again with growing delays instead of failing at once. Only permanent errors are treated as bounces, and those addresses are added to your suppression list so they are not tried again.

  • Automatic retries with growing delays
  • Permanent failures stop immediately
  • Failed addresses join your suppression list

Questions about sending

Do I need my own domain?

Yes. You verify a domain you own by adding DNS records, then send from any address on it.

Can I send attachments?

Yes, within a size limit that is listed in the API reference.

What happens when an address bounces?

It is added to your suppression list and future sends to it are skipped, so your bounce rate stays low.

Is SMTP supported?

The HTTP API comes first. SMTP credentials are planned for a later release.
