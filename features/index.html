Overview

How it fits together

Your application only ever talks to one API. Behind it, geserd verifies your domain, signs and queues outgoing mail, accepts inbound mail on the same domain, and turns every event into a webhook call your server can react to. Nothing about the underlying complexity, DNS, DKIM, retries, parsing, leaks into your code.

  • One API for both directions
  • DNS, signing and retries handled for you
  • Every piece visible in one dashboard

A few common questions

Do I need to use every feature?

No. Most people start with sending only and add receiving and webhooks later, on the same domain.

Where do I start?

The quickstart in the documentation walks through adding a domain and sending your first email.

Is there a free plan?

Yes, with sending and receiving both included, at lower limits than the paid plans.
