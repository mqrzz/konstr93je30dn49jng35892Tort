Anatomy of a message

Raw mail in, clean data out

Mail arrives as messy text. Geserd turns it into fields you can use. Hover over a field to see where it came from.

What arrives
Received: from mail.example.com by mx.yourdomain.com
From: Ada <ada@example.com>
To: hi@yourdomain.com
Subject: Re: Welcome
Message-ID: <7f31@example.com>
In-Reply-To: <9c2f7a10@yourdomain.com>
Content-Type: multipart/mixed; boundary=b1
 
--b1
Content-Type: text/plain

What happens next

Five checks before it reaches you

  1. 1
    Size checkMessages up to 10 MB are accepted, larger ones are refused politely.
  2. 2
    ParsingHeaders, text, HTML and attachment details are split into fields.
  3. 3
    Spam scoringEach message gets a score and a verdict, so you can filter before you reply.
  4. 4
    StoredThe message is saved in your dashboard and kept for your plan’s log period.
  5. 5
    WebhookYour server receives email.received and fetches the full message when it is ready.

Questions about receiving

What do I need to start receiving?

A verified domain and one MX record pointing at Geserd. The dashboard shows the exact value to publish.

Does the webhook include the message body?

No. It carries the id, sender, recipients and subject. Fetch the full message, with text, HTML, attachment details and spam score, with one API call.

How large can an incoming message be?

Up to 10 MB including attachments. Anything larger is refused and the sender is told.
