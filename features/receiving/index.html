Inbound

Point MX. We do the rest.

Add a single MX record and geserd starts accepting mail for your domain. Each message is checked, parsed and stored, then shown in your dashboard and delivered to your server. Receiving works next to sending on the same domain: sending needs SPF and DKIM records, receiving needs an MX record, and the two never get in each other's way.

Webhook

Every message as structured data

You never parse MIME yourself. When a message arrives, your endpoint receives clean JSON with the sender, the recipients, the subject and both the text and HTML bodies. If your server is down, geserd retries the delivery, and the message stays safely stored in your inbox view either way.

  • Delivered to your webhook as it arrives
  • Retried when your server is down
  • Attachments available through the API

Reply

Reply with the same API

To answer a message, send a new email and set in_reply_to to the id of the message you received. geserd adds the In-Reply-To and References headers for you, so mail clients group your answer with the original in a single conversation. Your reply goes through the same signing, queue, retries and logs as any other email.

  • Threading headers added for you
  • Same delivery, logs and events
  • Reply from any address on your domain
POST /api/emails

Questions about receiving

Can I receive and send on the same domain?

Yes. Sending needs SPF and DKIM records, receiving needs an MX record. They do not conflict.

What if my webhook is down?

Delivery is retried, and the message stays stored in your inbox view either way.

Do you filter spam?

Inbound limits apply to every account. Spam filtering is on the roadmap.

Are there limits?

Yes, per plan. The pricing page lists the inbound volume of each plan.
