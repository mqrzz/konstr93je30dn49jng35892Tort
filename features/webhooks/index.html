Payload

Small, predictable payloads

Every event has the same envelope: a type, a timestamp and a data object that matches the type. There is no schema to memorize event by event, no deeply nested structures, just the fields you actually need to update your own database or notify a user.

  • Signed so you can verify the sender
  • Retried when your endpoint fails
  • Same format for inbound and outbound events

Reliability

Delivered even when your server is not

If your endpoint returns an error or does not answer in time, geserd retries the delivery with growing delays. You can see every attempt, its status code and the response your server sent, so debugging a missed webhook does not mean digging through your own logs first.

  • Delivery attempts logged in full
  • Backoff between retries
  • HTTPS endpoints only, for safety

Questions about webhooks

How do I verify a webhook?

Compare the signature header with an HMAC of the request body computed using your endpoint secret.

What should my endpoint return?

Any 2xx status means received. Any other response, or a timeout, is retried.

Can I replay an event?

Every delivery attempt is logged. Manual replay from the dashboard is planned for a later release.

Is there a timeout?

Yes. Respond quickly with a 2xx and process the work in the background of your own server.
