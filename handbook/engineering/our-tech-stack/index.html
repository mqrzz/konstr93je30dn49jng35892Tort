What is our tech stack

Reading time4 min
Updated2026-10-14
AuthorsGGeserd team

We pick boring, well understood tools and spend our effort on the parts that are specific to email.

The shape of the system

Geserd has two parts. The website, the documentation and the dashboard are plain HTML, CSS and JavaScript served as static files. The API behind them is a Node.js application using Express, with PostgreSQL for data. There is no front-end framework to update and no build step that can break on a Friday: what you read in the repository is what the browser receives.

Mail on our own servers

Outgoing and incoming mail goes through a mail server we run ourselves, not through another provider’s sending service. We sign every message with DKIM, publish SPF and DMARC for our own domain, and keep the reverse DNS name of the server consistent with the name it introduces itself with. The same server accepts SMTP submission on ports 465 and 587, where the password is simply an API key, so older applications can connect without code changes.

Why we keep it small

  • Fewer moving parts means fewer 3 a.m. surprises. Every dependency we add is a thing that can break, be abandoned or ship a vulnerability.
  • One person can hold it in their head. A system you can read from top to bottom is a system you can fix quickly.
  • Speed is a feature. Static pages and a small API are fast without clever tricks.

When a new need arrives, the question is not “which tool is fashionable” but “what is the least we must add to meet it”.
